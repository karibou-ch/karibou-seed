# **KARIBOU — PLAN DE MIGRATION UX 2026**

## **Objectif**

Aligner la stack technique sur la **Stratégie UX 2026** (cf. `3. Karibou.ch - Stratégie UX.md`) — soit :

* **Architecture de navigation à 4 niveaux** :
  * **N0 — Marché (QUI)** : selector marché soft dans le header (Particulier · Entreprise · Collectivité)
  * **N1 — Service (QUOI)** : 3 intentions (Courses · Abonnements · Apéro & buffet) + James transverse
  * **N2 — Contexte service** : Panel Side variable selon la page
  * **N3 — Opérationnel** : Compte / Panier
* **3 marchés racines** (= 3 publics) ayant chacun leurs routes SEO (`/`, `/entreprise`, `/ecoles`)
* **3 intentions** côté services (`Collectivity` n'est PAS une intention — c'est un marché racine)
* **Curation > Filtre** : chaque marché est une curation configurable ; playlists thématiques en sous-curation
* **Multi-tagging produit** + visibilité par marché (`ProductMarketScope`) — un produit = un enregistrement, N marchés
* **Backoffice de curation** = pré-requis bloquant (sans lui, ne pas démarrer)

> **Lecture commune** : ce document est le *plan de migration* ; la *stratégie* (vocabulaire, principes directeurs, schémas conceptuels) est dans `3. Karibou.ch - Stratégie UX.md`. En cas de divergence, la stratégie prime.

## **1. ARCHITECTURE NAVIGATION 4 NIVEAUX**

### **1.1 Vue d'ensemble**

| Niveau | Description | Implémentation |
|--------|-------------|----------------|
| **N0 - Marché (QUI)** | Selector marché racine — soft, persistance cookie | `NAV_MARKET_ITEMS` *(nouveau)* + `MarketContextService` |
| **N1 - Services (QUOI)** | Navigation inter-services (3 intentions + James) | `NAV_SERVICE_ITEMS` - variable homogène |
| **N2 - Contexte** | Navigation intra-service (+ playlists thématiques) | Panel Side par composant |
| **N3 - Opérationnel** | Compte, commandes, factures | Drawer/Modal dédié |

### **1.2 Niveau 0 : Marché (NAV_MARKET_ITEMS)** *(nouveau)*

```
┌──────────────────────────────────────────────────────────────────────────┐
│                        NAV_MARKET_ITEMS                                  │
├──────────────────────┬──────────────────────┬──────────────────────────────┤
│ 👤 Particulier       │ 🏢 Entreprise        │ 🏫 Collectivité              │
│ /                    │ /entreprise          │ /ecoles                      │
│ (par défaut)         │                      │                              │
└──────────────────────┴──────────────────────┴──────────────────────────────┘
```

* **Soft** : pas de landing forcée. Visiteur non identifié → Particulier par défaut.
* **Persistance** : cookie/session (clé `karibou.market`, durée 1 an).
* **SEO** : routes dédiées indexables par marché.
* **Switch** : toujours visible dans le header (toutes pages).

### **1.3 Niveau 1 : Services (NAV_SERVICE_ITEMS)**

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        NAV_SERVICE_ITEMS                                │
├──────────┬──────────┬───────────────┬──────────────────┬─────────────────┤
│ 🏠 Hub   │ 🛒 Courses│ 🔄 Abonnements│ 🎉 Apéro&buffet  │ 💬 James         │
│ /        │ /home    │ /subscriptions│ /buffet          │ /assistant/james │
│          │          │               │                  │ (transverse)     │
└──────────┴──────────┴───────────────┴──────────────────┴─────────────────┘
```

> **Variations contextuelles** : sur Marché Collectivité, le label `🎉 Apéro & buffet` peut s'afficher en *« Goûter & pique-nique »* via i18n contextuel par marché. La route `/buffet` reste la même ; la curation produit + le vocabulaire s'adaptent.

> **`collectivity` n'est plus dans `NAV_SERVICE_ITEMS`** — déplacé vers `NAV_MARKET_ITEMS` comme marché racine.

### **1.4 Niveau 2 : Contexte Service (Panel Side)**

| Service | Panel Side | Panel Right |
|---------|------------|-------------|
| `/home` | Categories, Boutiques, Thèmes, Favoris, **Playlists actives** | Calendrier, Aide |
| `/buffet` | Formulaire, Kits, Produits buffet, **Playlists buffet** | Récapitulatif, Assistant |
| `/subscriptions` | Contrats, Créer, Historique | Calendrier, Assistant |
| `/assistant` | Questions rapides, Historique | Produits suggérés |

> **Playlists thématiques** *(nouveau)* : sélections éditoriales secondaires dans un marché racine (ex. *« Apéro de fête »*, *« Goûter rentrée »*). Apparaissent en bloc HOME et via route SEO `/{marche}/playlists/{slug}`. Pas dans la nav principale. Cf. §5bis stratégie.

### **1.5 Panier vs Contrats**

| Service | Panier | Explication |
|---------|--------|-------------|
| `/home` | ✅ | Ajout produits → /cart/default |
| `/buffet` | ✅ | Kits click-buy → /cart/default |
| `/subscriptions` | ❌ | **Contrats** (pas un panier) |
| `/assistant` | ✅ | Panier vocal → /cart/default |

**⚠️ Subscriptions = Contrats**
- Configuration : récurrence + produits + adresse
- Modifiable/pausable à tout moment

### **1.6 Identification du marché actif (UX transverse)**

Dans tous les écrans (Hub, Home, Buffet, Subs, Assistant) :
* Le **selector marché** du header reste visible (pills desktop/tablet, dropdown compact mobile)
* Une **pastille colorée + label** rappellent le marché actif (ex. *« 👤 Particulier »*) en permanence
* Le passage d'un marché à un autre **conserve le panier** *(à confirmer côté UX-back : voir §3.3)* mais peut filtrer la disponibilité des items selon `ProductMarketScope.markets[]`

**Caractéristiques Home :**
- **Panel Side (gauche) = Catégories uniquement.** Liste plate, filtrée par la curation racine du marché actif. Pas de sous-blocs Boutiques/Thèmes/Favoris (déplacés dans le centre comme sélections).
- **Panel Center = feed de Sélections curatoriales** (pas une grille produits par catégorie). Ordre type :
  1. **📅 Disponible aujourd'hui / date livraison** (cartes produits dispo pour la date sélectionnée)
  2. **⭐ Vos favoris** (si client connecté avec historique)
  3. **🎨 Playlists thématiques actives** sur le marché (ex. *« Apéro de fête »*, *« Goûter rentrée »*) — cf. stratégie §5bis
  4. **🌱 De saison** (curation James / éditoriale)
  5. **🔁 Re-commander** (dernière commande, si client connecté)
  6. **🆕 Nouveautés** (produits récemment ajoutés à la curation racine)
- **Bascule** : un clic sur une catégorie dans le Panel Side fait basculer le centre en vue produits filtrés (grid classique). Le bouton « ← Sélections » revient au feed.
- **Filtré par marché actif** : toutes les sélections + catégories respectent `ProductMarketScope.markets[]` du marché courant. Cf. §3.4.
- **Recherche** : remontée dans le header (à côté du panier) pour libérer le centre.
- **Panel Right** : Calendrier livraison · Commande en cours · Aide James.
- **Sources d'offre** : affichées via badges produits (ex. *« Halle de Rive »*, *« Ferme de Budé »*) — pas comme entrée de nav, juste contextuel.
- Panier accessible via bottom bar et header.

**Pourquoi un feed de sélections au centre (et pas une grille catégories) ?**
- Aligne sur la stratégie *Curation > Filtre* : le client découvre par sélection éditoriale d'abord, par catégorie ensuite.
- Met en valeur les **Playlists thématiques** et les recommandations James.
- La grille par catégorie reste accessible en 1 clic (Panel Side).
